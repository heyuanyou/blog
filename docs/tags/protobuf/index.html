gRPC：高性能 RPC 框架的面试题

1. 基础概念 (Fundamentals) Q: 什么是 gRPC？它的核心优势是什么？ gRPC 是一个由 Google 开源的高性能、开源和通用的 RPC（远程过程调用）框架。它基于 HTTP/2 协议传输，使用 Protocol Buffers 作为接口描述语言（IDL）和消息序列化格式。 核心优势： 高性能 (High Performance)：基于 HTTP/2 设计，支持双向流、多路复用、头部压缩，相比 HTTP/1.1 + JSON 效率更高。 多语言支持 (Polyglot)：IDL (Proto 文件) 定义一次，可自动生成多种语言（Go, Java, Python, C++ 等）的客户端和服务端代码。 强类型约束 (Strongly Typed)：Protobuf 提供了严格的类型检查和版本兼容性，减少了集成时的契约错误。 生态丰富：内置支持负载均衡、追踪、健康检查和身份验证。 Q: 为什么选择 gRPC 而不是 RESTful API？ 特性 gRPC RESTful API (JSON/HTTP) 协议 HTTP/2 (二进制) 通常 HTTP/1.1 (文本) 数据格式 Protocol Buffers (二进制，小且快) JSON (文本，冗余大，解析慢) 通信模式 Unary, Client/Server/Bi-di Streaming Request-Response (全双工需要 WebSocket) API 定义 严格 (.proto 文件) 宽松 (OpenAPI/Swagger) 代码生成 原生支持 需要第三方工具 适用场景 内部微服务、高性能要求、多语言环境 外部 API、浏览器客户端、资源导向 Q: gRPC 的弱点是什么？ 浏览器支持有限：Web 浏览器主要通过 HTTP/1.1 与服务器交互，无法直接支持 gRPC 的 HTTP/2 帧和 Trailer。通常需要代理（如 gRPC-Web）。 调试困难：二进制协议不可读，需要专门工具（如 grpcurl）进行抓包和调试。 学习曲线：需要理解 IDL、Protobuf 和 HTTP/2 的概念。 2.
