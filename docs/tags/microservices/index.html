gRPC：高性能 RPC 框架的面试题

1. 基础概念 (Fundamentals) Q: 什么是 gRPC？它的核心优势是什么？ gRPC 是一个由 Google 开源的高性能、开源和通用的 RPC（远程过程调用）框架。它基于 HTTP/2 协议传输，使用 Protocol Buffers 作为接口描述语言（IDL）和消息序列化格式。 核心优势： 高性能 (High Performance)：基于 HTTP/2 设计，支持双向流、多路复用、头部压缩，相比 HTTP/1.1 + JSON 效率更高。 多语言支持 (Polyglot)：IDL (Proto 文件) 定义一次，可自动生成多种语言（Go, Java, Python, C++ 等）的客户端和服务端代码。 强类型约束 (Strongly Typed)：Protobuf 提供了严格的类型检查和版本兼容性，减少了集成时的契约错误。 生态丰富：内置支持负载均衡、追踪、健康检查和身份验证。 Q: 为什么选择 gRPC 而不是 RESTful API？ 特性 gRPC RESTful API (JSON/HTTP) 协议 HTTP/2 (二进制) 通常 HTTP/1.1 (文本) 数据格式 Protocol Buffers (二进制，小且快) JSON (文本，冗余大，解析慢) 通信模式 Unary, Client/Server/Bi-di Streaming Request-Response (全双工需要 WebSocket) API 定义 严格 (.proto 文件) 宽松 (OpenAPI/Swagger) 代码生成 原生支持 需要第三方工具 适用场景 内部微服务、高性能要求、多语言环境 外部 API、浏览器客户端、资源导向 Q: gRPC 的弱点是什么？ 浏览器支持有限：Web 浏览器主要通过 HTTP/1.1 与服务器交互，无法直接支持 gRPC 的 HTTP/2 帧和 Trailer。通常需要代理（如 gRPC-Web）。 调试困难：二进制协议不可读，需要专门工具（如 grpcurl）进行抓包和调试。 学习曲线：需要理解 IDL、Protobuf 和 HTTP/2 的概念。 2. 服务发现与注册详解：微服务架构的核心组件 什么是服务发现与注册？ 服务发现（Service Discovery）是微服务架构中的一个重要模式，用于自动检测和定位网络上的服务实例。服务注册（Service Registration）是服务实例向服务注册中心注册自己的过程。 核心问题： 在微服务架构中，服务实例是动态变化的（启动、停止、扩缩容），客户端如何找到可用的服务实例？ 传统方式的问题： 硬编码服务地址：服务地址变更需要修改代码 负载均衡器配置：需要手动配置，难以动态更新 DNS：更新延迟，不支持健康检查 服务发现的优势： 动态发现：自动发现服务实例 负载均衡：自动分发请求 健康检查：自动剔除不健康的实例 高可用：支持多实例部署 目录 为什么需要服务发现？ 服务发现模式 服务注册中心 常见服务发现工具 实现原理 应用场景 最佳实践 常见问题 总结 为什么需要服务发现？ 微服务架构的挑战 1. 服务实例动态变化 服务启动 → 注册到注册中心 服务停止 → 从注册中心注销 服务扩缩容 → 注册中心自动更新 2. 服务地址管理困难 服务实例可能有多个（负载均衡） 服务可能部署在不同环境（开发、测试、生产） 服务可能迁移到不同的服务器 3. 服务健康状态 需要知道哪些服务实例是健康的 需要自动剔除不健康的实例 需要支持服务降级 服务发现的价值 1. 解耦服务 服务提供者和消费者解耦 不需要硬编码服务地址 2. 动态负载均衡 自动选择健康的服务实例 支持多种负载均衡策略 3. 高可用 自动故障转移 支持多实例部署 4. 服务治理 服务监控 流量管理 配置管理 服务发现模式 1. 客户端发现（Client-Side Discovery） 工作原理： ...
