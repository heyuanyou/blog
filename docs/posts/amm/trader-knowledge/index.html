做市策略知识手册#

基于 Trader Tool 原型图，讲解做市基础知识、策略原理与实操示例

1. 什么是做市？#

1.1 基本概念#

做市（Market Making） 是指在交易市场中同时挂出买单和卖单，为市场提供流动性，并通过买卖价差（Spread）获利的行为。

盘口示例：

卖单（Ask）          买单（Bid）
─────────────        ─────────────
0.0032  500个         0.0028  800个   ← 做市商挂单
0.0031  300个         0.0027  600个
0.0030  200个   ↑     0.0026  400个
              Spread = 0.0002 (价差)

做市商的角色：

  • 提供流动性：让其他交易者能快速成交
  • 赚取价差：低买高卖，赚中间的 Spread
  • 承担库存风险：持有的币可能贬值

1.2 做市 vs 交易#

维度做市商普通交易者
目标赚价差，保持中性赚价格波动
持仓尽量对冲，不囤货有方向性持仓
频率高频挂撤单低频买卖
风险库存风险、逆向选择价格风险

2. 策略类型详解#

2.1 Active Pump（主动拉盘）#

原理： 通过连续市价买入，消耗卖盘深度，推动价格上涨到目标价。

执行过程：

时间轴 ────────────────────────────────────→
       │                                    │
    开始价格                              目标价格
     0.0028                               0.0031
       │        持续市价买入                │
       ├──────────────────────────────────→│
       │    MaxSpend: 3000U                │
       │    Duration: 30min                │

参数说明：

参数含义示例
Target目标价格（或涨幅%）0.0031 或 +10%
MaxSpend最大花费（USDT）3000 U
SubAccts参与账户数5 个子账户轮流下单
Duration持续时间30 分钟
RevTrade反向交易比例达到目标后卖出 20%

使用场景：

  • 项目方需要拉升币价
  • 配合利好消息发布
  • 突破关键阻力位

示例操作：

场景：UAI 当前价格 0.0028，需要在 30 分钟内拉到 0.0031

配置：
  Exchange: Binance, OKX
  Target: 0.0031 (Price)
  MaxSpend: 3000 U
  SubAccts: 5 个账户
  Duration: 30 min
  RevTrade: 20%

执行逻辑：
  1. 引擎每 5 秒（Tick）检查当前价格
  2. 若价格 < 目标，从 5 个账户轮流市价买入
  3. 单次买入金额 = 剩余预算 / 剩余时间 × Tick
  4. 达到目标价或预算耗尽后停止
  5. RevTrade 20%：卖出已买入数量的 20%（获利了结）

2.2 Active Dump（主动砸盘）#

原理： 与 Pump 相反，通过连续市价卖出，消耗买盘深度，压低价格。

执行过程：

价格
  ↑
0.0028 ┤ ●────┐
       │      │ 持续市价卖出
0.0026 │      │
       │      ▼
0.0024 ┤      ●  ← 目标价格
       └──────────────→ 时间

使用场景：

  • 需要低价吸筹
  • 配合利空消息
  • 打压竞争对手代币

示例操作：

场景：需要把 UAI 从 0.0028 压到 0.0024

配置：
  Exchange: Binance, OKX
  Target: 0.0024 (Price)
  MaxSpend: 2000 U（实际是卖出等值的币）
  SubAccts: 3 个账户
  Duration: 25 min
  RevTrade: 20%（砸完后买回 20%）

2.3 Passive Grid（被动网格）#

原理： 在当前价格上下挂多层限价单，形成网格。价格波动时自动低买高卖，赚取网格利润。

网格示意图：

价格    挂单类型    数量
─────────────────────────
0.0034   卖单      100 × 1.2³
0.0032   卖单      100 × 1.2²
0.0030   卖单      100 × 1.2    ← 1stSpread (首单价差)
─────── 当前价 0.0028 ───────
0.0026   买单      100 × 1.2    ← 1stSpread
0.0024   买单      100 × 1.2²
0.0022   买单      100 × 1.2³   ← MaxLevels = 3层
         
GridGap = 0.0002 (每层间距)
QtyMultiplier = 1.2 (越远数量越大)

参数详解（三组）：

第一组：基础资源

参数含义示例
SubAccts用几个账户跑5 个账户
InitMrgn每个账户投入保证金25 U × 5 = 125 U 总投入

第二组：盘口形态

参数含义示例
1stSpread首单离当前价多远0.08% → 第一层挂在 ±0.08%
GridGap每层之间间距0.08% → 层与层相隔 0.08%
MaxLevels最多铺几层8 层 → 上下各 8 层
QtyMultiplier数量倍数1.2 → 越远层数量越大

第三组：库存与风控

参数含义示例
TargetDelta目标持仓0 = 保持中性，正数 = 偏多
RebalanceThr再平衡阈值20% → 仓位偏离 20% 时调整
SprdRed价差压缩强度0.1$ → 风控时收紧挂单
InitPosDelta初始仓位0 = 空仓启动

使用场景：

  • 震荡行情做市赚价差
  • 为代币提供流动性
  • 长期稳定的做市策略

示例操作：

场景：UAI 在 0.0025-0.0035 区间震荡，做网格

配置：
  Exchange: Binance
  SubAccts: 5 个账户
  InitMrgn: 25 U（每账户）
  1stSpread: 0.08%
  GridGap: 0.08%
  MaxLevels: 8
  QtyMultiplier: 1.2
  TargetDelta: 0（保持中性）
  RebalanceThr: 20%

执行逻辑：
  1. 在当前价 ±0.08% 处挂首层买卖单
  2. 每隔 0.08% 铺一层，共 8 层
  3. 买单成交后，在上方挂对应卖单（赚网格利润）
  4. 若持仓偏离目标超 20%，触发再平衡
  5. 引擎每 Tick 检查并调整挂单

网格利润计算：

假设：
  - 每层间距 0.08%
  - 每次成交 100 U
  
单次网格利润 = 100 × 0.08% × 2 = 0.16 U
（买入后在上方卖出，赚两个间距）

日成交 50 次 = 50 × 0.16 = 8 U/天

2.4 Manual Intervention Open（手动干预开仓）#

原理： 一次性在多个账户批量开仓，用于快速建仓或加仓。

批量开仓示意：

账户列表              操作
──────────────────────────────
Bn_B_01  ──→  Open Long  400 U
Bn_B_02  ──→  Open Long  400 U
Bn_B_03  ──→  Open Long  400 U
Bn_B_04  ──→  Open Long  400 U
Bn_B_05  ──→  Open Long  400 U
                        ────────
               Total:   2000 U

参数说明：

参数含义示例
SubAccts开仓账户数5 个（不得大于选中账户数）
Total Spend总开仓金额2000 U（平分到各账户）
方向Long / ShortOpen Long = 做多

使用场景：

  • 快速批量建仓
  • 配合 Pump 前提前布局
  • 多账户分散风险

示例操作：

场景：准备拉盘前，先用 5 个账户建多仓

配置：
  Exchange: Binance
  SubAccts: scope(all, 5) → 选中的账户里用 5 个
  Total Spend: 2000 U
  操作: Open Long

执行结果：
  - 5 个账户各开多 400 U
  - 总持仓 2000 U 做多

2.5 Emergency Close（紧急平仓）#

原理： 快速按比例平掉多个账户的仓位，用于风控或止损。

紧急平仓示意：

账户        当前仓位      平仓比例    平仓数量
──────────────────────────────────────────────
Bn_B_01    Long 1000 U    20%        平 200 U
Bn_B_02    Long 800 U     20%        平 160 U
Bn_B_03    Long 600 U     20%        平 120 U

参数说明：

参数含义示例
Close Accts Pos选择账户范围scope(all, 5)
% ofPos平仓比例20% = 每个账户平自己仓位的 20%
方向Close Long / Close Short平多仓 / 平空仓

使用场景：

  • 行情突变紧急止损
  • 部分获利了结
  • 快速降低风险敞口

示例操作：

场景：行情突然下跌，需要快速平掉 50% 多仓

配置：
  Exchange: Global（所有交易所）
  Close Accts Pos: 所有账户
  % ofPos: 50%
  操作: Close Long

执行结果：
  - 所有账户的多仓各平掉 50%
  - 快速降低风险敞口

3. 组合策略示例#

3.1 拉盘套利组合#

阶段一：布局（Manual Intervention）
  └─ 5 个账户各开多 400 U，总计 2000 U

阶段二：拉盘（Active Pump）
  └─ 目标涨 10%，花费 3000 U 推价格

阶段三：出货（RevTrade 自动 + Emergency Close）
  └─ RevTrade 20% 自动卖出
  └─ 手动 Emergency Close 平掉剩余仓位

盈利计算（理想情况）：
  成本：2000 U 持仓 + 3000 U 拉盘 = 5000 U
  收益：2000 U × 10% = 200 U（仓位盈利）
       + 3000 U 买入的币升值
  实际盈利取决于出货滑点和市场深度

3.2 震荡行情做市#

配置 Passive Grid：
  - 区间：0.0025 - 0.0035
  - 8 层网格
  - 每层 0.08% 间距
  - 投入 500 U

预期收益：
  - 假设日均成交 100 次
  - 每次利润 0.16 U
  - 日收益约 16 U（3.2% 日化）

风险：
  - 价格单边突破区间
  - 需要 Emergency Close 止损

3.3 砸盘吸筹#

阶段一：砸盘（Active Dump）
  └─ 目标跌 15%，卖出 2000 U 等值的币

阶段二：吸筹（Passive Grid）
  └─ 在低位布置买单网格
  └─ 逐步吸收恐慌盘

阶段三：反弹（Active Pump）
  └─ 价格回升，低价筹码获利

4. 风控要点#

4.1 全局配置的作用#

配置风控作用
MaxErr = 10连续 10 次失败自动停止，防止故障
CapLmt = 60%最多用 60% 保证金，留缓冲防爆仓
MinSize = 1000 U避免碎单，控制成本
PriceTol = 0.01$减少频繁撤改单

4.2 常见风险#

风险描述应对
库存风险持有的币价下跌TargetDelta = 0 保持中性
滑点风险大单成交价格偏离分账户分批执行
API 故障网络/交易所问题MaxErr 保护
逆向选择知情交易者吃单1stSpread 设大些

4.3 紧急情况处理#

情况一：价格暴跌
  → Emergency Close 快速平多仓
  → 或 Active Dump 配合出货

情况二：价格暴涨（空仓被打爆）
  → Emergency Close 快速平空仓

情况三：API 故障
  → MaxErr 触发保护模式
  → 人工检查后恢复

5. 关键指标监控#

5.1 策略运行状态#

从 Running Strategies 面板监控：

指标含义健康值
Spend已花费金额< MaxSpend
Duration运行时长< EndTime
Price vs Target当前价 vs 目标价进度条显示
Total Delta总持仓偏移接近 0（中性）

5.2 Command Audit 审计#

所有操作都会记录：

04:07 Jerry    Set Spread 0.10% -> 0.15%     Success
10:10 System   Binance Active Pump (...)     Failed
08:02 Jerry    Emergency Close 50%           Success

用于追溯问题和责任归属。

6. 术语表#

术语英文含义
做市Market Making提供买卖流动性
价差Spread买一和卖一的差价
滑点Slippage实际成交价与预期的偏差
深度Depth盘口挂单量
DeltaDelta持仓方向偏移（正=多，负=空）
网格Grid多层挂单形成的价格网络
再平衡Rebalance调整持仓回到目标
子账户SubAccts分散操作的多个账户
TickTick策略引擎执行周期

7. 快速参考卡片#

Active Pump/Dump 配置模板#

Exchange: Binance, OKX        # 交易所
Target: 0.0031 / +10%         # 目标价格或涨跌幅
MaxSpend: 3000 U              # 最大花费
SubAccts: 5                   # 账户数
Duration: 30 min              # 持续时间
RevTrade: 20%                 # 完成后反向比例

Passive Grid 配置模板#

# 基础资源
SubAccts: 5                   # 账户数
InitMrgn: 25 U                # 每账户保证金

# 盘口形态
1stSpread: 0.08%              # 首单价差
GridGap: 0.08%                # 层间距
MaxLevels: 8                  # 层数
QtyMultiplier: 1.2            # 数量倍数

# 风控
TargetDelta: 0                # 目标中性
RebalanceThr: 20%             # 再平衡阈值
SprdRed: 0.1$                 # 风控压缩
InitPosDelta: 0               # 初始仓位

紧急操作速查#

快速平多仓: Emergency Close → 50% ofPos → Close Long
快速平空仓: Emergency Close → 50% ofPos → Close Short
批量开多:  Manual Intervention → 2000 U → Open Long
批量开空:  Manual Intervention → 2000 U → Open Short
