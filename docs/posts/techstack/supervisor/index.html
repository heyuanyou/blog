基础概念#

1. 什么是 Supervisor？它有哪些特点？#

答案：

Supervisor 是一个用 Python 编写的进程监控和管理工具，用于在类 Unix 系统上管理进程。

主要特点：

  • 自动重启：进程异常退出时自动重启
  • 进程管理：统一管理多个进程的启动、停止、重启
  • 日志管理：集中管理进程的标准输出和错误输出
  • Web UI：提供 Web 界面查看和管理进程
  • 进程组：支持进程组管理，批量操作
  • 事件通知：支持事件监听和通知机制
  • 简单易用：配置文件简单，易于理解

应用场景：

  • Web 应用：管理 Gunicorn、uWSGI 等应用服务器
  • 后台任务：管理 Celery Worker、定时任务等
  • 服务守护：确保关键服务持续运行
  • 开发环境：统一管理开发环境中的多个服务

2. Supervisor 的架构是什么？#

答案：

Supervisor 采用客户端-服务器架构：

Supervisord（主进程）
  ├─ 读取配置文件
  ├─ 启动子进程
  ├─ 监控进程状态
  ├─ 管理日志
  └─ 提供 RPC 接口

Supervisorctl（客户端）
  ├─ 连接 Supervisord
  ├─ 发送控制命令
  └─ 查看进程状态

Web UI（可选）
  ├─ HTTP 服务器
  ├─ 显示进程状态
  └─ 提供控制界面

核心组件：

  1. supervisord：主进程，负责启动和管理子进程
  2. supervisorctl：命令行客户端，用于控制 supervisord
  3. Web UI：Web 界面（可选）
  4. XML-RPC：RPC 接口，用于程序化控制

python setup.py install

5. Supervisor 的配置文件在哪里？#

答案：

配置文件位置：

  • 主配置文件：/etc/supervisor/supervisord.conf（系统安装）
  • 用户配置：~/.supervisord.conf（用户安装）
  • 默认位置：/etc/supervisord.conf

查找配置文件：

# 查看默认配置文件位置
supervisord -c /etc/supervisor/supervisord.conf -n

# 或使用 echo_supervisord_conf 生成默认配置
echo_supervisord_conf > /etc/supervisor/supervisord.conf

配置文件结构：

[unix_http_server]
file=/var/run/supervisor.sock

[supervisord]
logfile=/var/log/supervisor/supervisord.log
pidfile=/var/run/supervisord.pid

[rpcinterface:supervisor]
supervisor.rpcinterface_factory = supervisor.rpcinterface:make_main_rpcinterface

[supervisorctl]
serverurl=unix:///var/run/supervisor.sock

[include]
files = /etc/supervisor/conf.d/*.conf

配置文件详解#

7. supervisord 配置段有哪些选项？#

答案：

supervisord 配置段：

[supervisord]
# 日志文件
logfile=/var/log/supervisor/supervisord.log
logfile_maxbytes=50MB        # 单个日志文件最大大小
logfile_backups=10           # 保留的日志文件备份数
loglevel=info                # 日志级别：critical, error, warn, info, debug, trace, blather

# PID 文件
pidfile=/var/run/supervisord.pid

# 运行模式
nodaemon=false               # 是否在前台运行（false=后台运行）

# 资源限制
minfds=1024                  # 最小文件描述符数
minprocs=200                 # 最小进程数

# 用户和组
user=root                    # 运行用户
umask=022                    # 文件权限掩码

# 环境变量
environment=KEY1="value1",KEY2="value2"

# 目录
directory=/tmp               # 工作目录

重要选项说明：

  • logfile：主日志文件路径
  • loglevel：日志详细程度，生产环境建议 info 或 warn
  • nodaemon：开发调试时设为 true，生产环境设为 false
  • minfds/minprocs：系统资源限制，需要根据实际情况调整

8. 如何配置进程（program）？#

答案：

基本配置：

[program:myapp]
command=/usr/bin/python /path/to/myapp.py
directory=/path/to
user=www-data
autostart=true
autorestart=true
startretries=3
startsecs=10
redirect_stderr=true
stdout_logfile=/var/log/myapp.log
stdout_logfile_maxbytes=50MB
stdout_logfile_backups=10
stderr_logfile=/var/log/myapp_error.log
environment=PYTHONPATH="/path/to",HOME="/home/user"

配置选项详解：

选项说明默认值
command要执行的命令（必需）-
directory工作目录-
user运行用户当前用户
autostart是否自动启动true
autorestart是否自动重启unexpected
startretries启动失败重试次数3
startsecs启动后多少秒认为启动成功10
stopwaitsecs停止等待时间10
redirect_stderr是否重定向 stderr 到 stdoutfalse
stdout_logfile标准输出日志文件-
stderr_logfile错误输出日志文件-
environment环境变量-
priority启动优先级999

autorestart 选项：

  • false：不自动重启
  • true：总是自动重启
  • unexpected：意外退出时重启（默认）
  • unexpected + exitcodes：指定退出码时重启

示例：

[program:gunicorn]
command=/usr/local/bin/gunicorn -w 4 -b 0.0.0.0:8000 myapp:app
directory=/var/www/myapp
user=www-data
autostart=true
autorestart=true
startretries=3
startsecs=5
stopwaitsecs=30
redirect_stderr=true
stdout_logfile=/var/log/gunicorn.log
stdout_logfile_maxbytes=50MB
stdout_logfile_backups=5
environment=PYTHONPATH="/var/www/myapp"

10. 如何配置事件监听器（eventlistener）？#

答案：

事件监听器配置：

[eventlistener:myeventlistener]
command=/path/to/myeventlistener.py
events=PROCESS_STATE,TICK_60
buffer_size=10
environment=KEY1="value1"
stdout_logfile=/var/log/eventlistener.log
stderr_logfile=/var/log/eventlistener_error.log

事件类型：

  • PROCESS_STATE：进程状态变化
  • PROCESS_STATE_STARTING：进程启动中
  • PROCESS_STATE_RUNNING：进程运行中
  • PROCESS_STATE_BACKOFF：进程启动失败
  • PROCESS_STATE_STOPPING：进程停止中
  • PROCESS_STATE_EXITED：进程退出
  • PROCESS_STATE_STOPPED：进程已停止
  • PROCESS_STATE_FATAL：进程致命错误
  • PROCESS_STATE_UNKNOWN：进程状态未知
  • TICK_5、TICK_60、TICK_3600：定时事件

事件监听器示例（Python）：

#!/usr/bin/env python
import sys
import json

def write_stdout(s):
    sys.stdout.write(s)
    sys.stdout.flush()

def write_stderr(s):
    sys.stderr.write(s)
    sys.stderr.flush()

def main():
    while True:
        write_stdout('READY\n')
        line = sys.stdin.readline()
        headers = dict([x.split(':') for x in line.split()])
        data = sys.stdin.read(int(headers['len']))
        event = json.loads(data)
        
        # 处理事件
        if event['eventname'] == 'PROCESS_STATE_EXITED':
            write_stderr('Process %s exited with code %s\n' % 
                        (event['processname'], event['expected']))
        
        write_stdout('RESULT 2\nOK')
        
if __name__ == '__main__':
    main()

11. 如何使用 supervisorctl 管理进程？#

答案：

基本命令：

# 查看所有进程状态
supervisorctl status

# 启动进程
supervisorctl start <program_name>

# 停止进程
supervisorctl stop <program_name>

supervisorctl restart <program_name>

supervisorctl tail -f <program_name>  # 实时查看

# 清除日志
supervisorctl clear <program_name>

交互式模式：

# 进入交互式模式
supervisorctl

# 在交互式模式中
supervisor> status
supervisor> start myapp
supervisor> stop myapp
supervisor> restart myapp
supervisor> tail myapp
supervisor> exit

批量操作：

# 启动所有进程
supervisorctl start all

# 停止所有进程
supervisorctl stop all

# 重启所有进程
supervisorctl restart all

# 操作进程组
supervisorctl start webapps:*
supervisorctl stop webapps:*

答案：

进程状态：

状态说明
STOPPED已停止
STARTING启动中
RUNNING运行中
BACKOFF启动失败，等待重试
STOPPING停止中
EXITED已退出
FATAL致命错误
UNKNOWN状态未知

查看状态：

worker2                          STOPPED   Nov 10 10:30 AM

状态转换：

STOPPED → STARTING → RUNNING
    ↑                    ↓
    ← EXITED ← STOPPING ←
    ↑
    ← BACKOFF (启动失败)

13. 如何配置进程自动重启策略？#

答案：

autorestart 选项：

[program:myapp]
# 不自动重启
autorestart=false

# 总是自动重启
autorestart=true

# 意外退出时重启（默认）
autorestart=unexpected
exitcodes=0,2          # 正常退出码（不重启）

配置示例：

[program:webapp]
command=/usr/bin/python /app/webapp.py
autorestart=unexpected
exitcodes=0            # 退出码为 0 时不重启
startretries=3         # 启动失败重试 3 次
startsecs=10           # 启动后 10 秒内退出视为启动失败
stopwaitsecs=30        # 停止时等待 30 秒

重启策略对比：

  • autorestart=false：进程退出后不重启，适合一次性任务
  • autorestart=true：总是重启，适合需要持续运行的服务
  • autorestart=unexpected：意外退出时重启，适合大多数场景

14. 如何设置进程优先级？#

答案：

优先级配置：

[program:database]
command=/usr/bin/mysqld
priority=100           # 高优先级，先启动

[program:webapp]
command=/usr/bin/python /app/webapp.py
priority=200           # 低优先级，后启动

[program:worker]
command=/usr/bin/python /app/worker.py
priority=300           # 最低优先级，最后启动

优先级规则：

  • 数字越小，优先级越高
  • 优先级高的进程先启动
  • 默认优先级为 999
  • 停止时按相反顺序停止

进程组优先级：

[group:core]
programs=db,cache
priority=100

[group:apps]
programs=webapp,api
priority=200

日志管理#

15. 如何配置日志文件？#

答案：

日志配置：

[program:myapp]
# 标准输出日志
stdout_logfile=/var/log/myapp.log
stdout_logfile_maxbytes=50MB      # 单个日志文件最大大小
stdout_logfile_backups=10         # 保留的备份文件数
stdout_capture_maxbytes=1MB        # 捕获的最大字节数
stdout_events_enabled=false       # 是否启用事件

# 错误输出日志
stderr_logfile=/var/log/myapp_error.log
stderr_logfile_maxbytes=50MB
stderr_logfile_backups=10
stderr_capture_maxbytes=1MB
stderr_events_enabled=false

# 重定向 stderr 到 stdout
redirect_stderr=true              # 合并到 stdout_logfile

日志轮转：

[program:myapp]
stdout_logfile=/var/log/myapp.log
stdout_logfile_maxbytes=50MB       # 达到 50MB 时轮转
stdout_logfile_backups=10         # 保留 10 个备份文件

日志文件命名：

  • 主日志：myapp.log
  • 备份日志：myapp.log.1, myapp.log.2, …, myapp.log.10

17. 如何配置日志级别？#

答案：

日志级别配置：

[supervisord]
loglevel=info          # 日志级别

日志级别：

级别说明使用场景
critical严重错误生产环境（最少日志）
error错误生产环境
warn警告生产环境（推荐）
info信息开发/测试环境（推荐）

blather详细跟踪最详细日志

推荐配置：

  • 生产环境：loglevel=warn 或 loglevel=error
  • 开发环境：loglevel=info
  • 调试问题：loglevel=debug

#!/usr/bin/env python
import sys
import json
import requests

def main():
    while True:
        sys.stdout.write('READY\n')
        sys.stdout.flush()
        line = sys.stdin.readline()
        headers = dict([x.split(':') for x in line.split()])
        data = sys.stdin.read(int(headers['len']))
        event = json.loads(data)
        
        if event['eventname'] == 'PROCESS_STATE_RUNNING':
            # 检查进程健康
            try:
                response = requests.get('http://localhost:8000/health', timeout=5)
                if response.status_code != 200:
                    # 健康检查失败，重启进程
                    sys.stderr.write('Health check failed, restarting...\n')
            except:
                sys.stderr.write('Health check error\n')
        
        sys.stdout.write('RESULT 2\nOK')
        sys.stdout.flush()

if __name__ == '__main__':
    main()

24. 如何实现进程监控和告警？#

答案：

使用事件监听器实现告警：

#!/usr/bin/env python
import sys
import json
import smtplib
from email.mime.text import MIMEText

def send_alert(process_name, event_name):
    msg = MIMEText('Process %s: %s' % (process_name, event_name))
    msg['Subject'] = 'Supervisor Alert'
    msg['From'] = 'supervisor@example.com'
    msg['To'] = 'admin@example.com'
    
    s = smtplib.SMTP('localhost')
    s.send_message(msg)
    s.quit()

def main():
    while True:
        sys.stdout.write('READY\n')
        sys.stdout.flush()
        line = sys.stdin.readline()
        headers = dict([x.split(':') for x in line.split()])
        data = sys.stdin.read(int(headers['len']))
        event = json.loads(data)
        
        if event['eventname'] == 'PROCESS_STATE_FATAL':
            send_alert(event['processname'], 'FATAL')
        elif event['eventname'] == 'PROCESS_STATE_EXITED':
            if event['expected'] == 0:
                send_alert(event['processname'], 'UNEXPECTED EXIT')
        
        sys.stdout.write('RESULT 2\nOK')
        sys.stdout.flush()

if __name__ == '__main__':
    main()

#!/usr/bin/env python
# prometheus_exporter.py
from prometheus_client import Counter, Gauge, start_http_server
import xmlrpc.client

# 指标定义
process_restarts = Counter('supervisor_process_restarts_total', 'Process restarts', ['process'])
process_uptime = Gauge('supervisor_process_uptime_seconds', 'Process uptime', ['process'])

def collect_metrics():
    server = xmlrpc.client.ServerProxy('http://localhost:9001/RPC2')
    processes = server.supervisor.getAllProcessInfo()
    
    for proc in processes:
        process_restarts.labels(process=proc['name']).inc(proc['spawnerr'] or 0)
        process_uptime.labels(process=proc['name']).set(proc['now'] - proc['start'])

if __name__ == '__main__':
    start_http_server(8000)
    while True:
        collect_metrics()
        time.sleep(10)

#!/usr/bin/env python
# supervisor_monitor.py
import xmlrpc.client
import json
import time

def check_processes():
    server = xmlrpc.client.ServerProxy('http://localhost:9001/RPC2')
    processes = server.supervisor.getAllProcessInfo()
    
    issues = []
    for proc in processes:
        if proc['statename'] != 'RUNNING':
            issues.append({
                'name': proc['name'],
                'state': proc['statename'],
                'exitcode': proc.get('exitcode'),
            })
    
    return issues

if __name__ == '__main__':
    while True:
        issues = check_processes()
        if issues:
            print(json.dumps(issues, indent=2))
        time.sleep(60)

常见问题与解决方案#

29. 进程无法启动怎么办？#

答案：

排查步骤：

  1. 检查配置文件语法：
supervisord -c /etc/supervisor/supervisord.conf -n
  1. 查看进程日志：
supervisorctl tail myapp
supervisorctl tail myapp stderr
  1. 检查命令路径：
which python
which gunicorn
  1. 检查权限：
ls -l /path/to/command
ls -l /path/to/logfile
  1. 手动执行命令：
# 手动执行，查看错误
/usr/bin/python /app/myapp.py

常见原因：

  • 命令路径错误
  • 权限不足
  • 依赖缺失
  • 端口被占用
  • 配置文件错误

30. 进程频繁重启怎么办？#

答案：

排查步骤：

  1. 查看进程状态：
supervisorctl status myapp
  1. 查看日志：
supervisorctl tail -1000 myapp stderr
  1. 检查启动时间：
[program:myapp]
startsecs=30              # 增加启动等待时间
  1. 检查重启策略：
[program:myapp]
autorestart=unexpected    # 改为 unexpected
exitcodes=0               # 正常退出不重启

常见原因：

  • 启动时间过长，被误判为失败
  • 进程立即退出（代码错误）
  • 端口冲突
  • 资源不足

33. Supervisor vs systemd#

答案：

特性Supervisorsystemd
适用场景应用进程系统服务
配置复杂度简单复杂
Web UI支持不支持

  • systemd：系统级服务，功能强大
